E1.2's schedule halved a learning rate inside a loop. A training script that halves rates in several places can write the halving once, as a function, and call it wherever it is needed. M1.3 wrote functions in the same way, with `def` and `return`. Here is one, and a program that calls it once.

```python
lr = 0.1

def halve(lr):
    lr = lr / 2
    return lr

smaller = halve(lr)
print(lr, smaller)
```

The name `lr` appears in two places: in the program, for the rate it starts with, and inside `halve`. Decide what the program prints before you run anything.

<Reveal for="puzzle-halve">

Until now each job in a program was written out where it was needed. Real programs are built from functions: jobs with names, each written once and called wherever it is needed, as `halve` is here. This lesson looks inside a call, at how it runs, which names it can see and which it can change. Then it asks why that matters. A function that keeps to its own names behaves like a function in M1.3, and functions like that can be checked one at a time, then put together into larger programs that can be trusted as a whole.
