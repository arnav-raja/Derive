## Truth values and sets in Python

Python has two truth values, `True` and `False`, and its comparisons give them: `3 < 5` is `True`, `2 == 3` is `False`, `!=` asks "not equal to", and `<=` and `>=` ask "at most" and "at least". Comparisons can be chained, so `1 <= x <= 10` means `1 <= x and x <= 10`. `and`, `or` and `not` follow the truth tables of Explore, and a function can return a truth value, as a predicate does:

```python
def is_short(words):
    return words < 50

print(is_short(12), is_short(80), not is_short(80))   # prints True False True
```

Python's sets are written with braces, as on paper: `{101, 102, 103}`. `x in A` asks whether `x` is an element of `A`. `A | B` is the union, `A & B` the intersection, and `A - B` the elements of `A` that are not in `B`, which is $A \cap B^c$ in Explore's notation: Python has no complement on its own, since it does not know the whole set $U$. Between two sets, write `|` and `&`, never `or` and `and`: `A and B` raises no error, but it gives `B` itself whenever `A` has an element, not the intersection. `len(A)` counts the elements, and `A <= B` asks whether `A` is a subset of `B`. The empty set is written `set()`, because `{}` is an empty *dictionary*, another kind of collection, which this phase's last exercise meets. A set prints its elements in an order of its own, which need not be the order they were written in, and that never matters, since a set has no order.

## A leak between training and test

A model is trained on one set of examples and tested on another. If an example is in both, the test asks the model about something it has already seen, and its score says more about its memory than about how well it will do on new data. ## Quantifiers in Python

`all(...)` is $\forall$ and `any(...)` is $\exists$, over the values that a `for` inside the brackets runs through:

```python
widths = [64, 256, 1024]
print(all(w >= 64 for w in widths))   # True: every width is at least 64
print(any(w > 1000 for w in widths))  # True: some width is more than 1,000
```

`[64, 256, 1024]` is a *list*, which keeps its values in order, and `for w in widths` makes `w` stand for each of them in turn. `all(w >= 64 for w in widths)` works out `w >= 64` for every `w` in the list and is `True` only if every result is `True`. `any` is `True` if at least one is. The `for` can run through a set, a list or `range(a, b)`, the whole numbers from `a` up to but not including `b`; with a third number, as in `range(0, 10000, 2)`, it counts in steps of that size.

One quantifier can sit inside another. The quantifier said first is the outer call, and the inner one runs again for each value of the outer one's `for`, which is written at the end of the outer call:

```python
xs = [3, 7]
print(all(any(x + y == 10 for y in xs) for x in xs))   # True: every x has a y that makes 10 with it
```

## Compare with the library

SymPy, the algebra library from M1.2 and M1.3, has a part for logic. `symbols("p q")` makes two symbols at once, one for each name. `And(p, q)`, `Or(p, q)` and `Not(p)` are the three words, `Implies(p, q)` is $p \Rightarrow q$, and `Equivalent(a, b)` is $a \Leftrightarrow b$, true when `a` and `b` have the same truth value. Python's own `and`, `or` and `not` do not build statements from SymPy's symbols: Python treats each symbol as true, so `p and q` is just `q`, with no error. A statement for SymPy is always written with `And`, `Or` and `Not`. `satisfiable(s)` looks for a row of the truth table that makes `s` true: it gives the values of one such row, as in `{p: True, q: False}`, a *dictionary* that pairs each letter with its value, or `False` if there is no such row. So `satisfiable(Not(Equivalent(a, b)))` is `False` exactly when `a` and `b` are equivalent, and otherwise it gives a row where they differ, a counterexample. `simplify_logic(s)` gives the simplest statement it can find that is equivalent to `s`.

A truth table settles such a question by trying every row: with two letters there are four, and each new letter doubles them, so a statement in 30 letters has more than a billion. `satisfiable` does not try them all. It is a small *SAT solver*: it gives one letter a value at a time and backs up as soon as a choice cannot work. SAT solvers built on the same idea, only far cleverer, settle questions much too large for a truth table, and they check hardware designs and software for bugs. `simplify_logic` found that the filter's two cases cover every email that is short, whatever its language, so the language never mattered.
