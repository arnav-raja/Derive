## Names refer to values

A program is a list of *statements*, and Python carries them out one at a time, from the top. The puzzle's script is made almost entirely of one kind, the *assignment*, such as `lr = base_lr * batch_size / 256`. An assignment always works in two moves. First Python works out the right side, using the values that the names refer to at that moment. Then it makes the name on the left refer to the result. A name used in this way is called a *variable*. M1.2 asked you to remember $x = x + 1$, an equation with no solution. In Python, `x = x + 1` is an assignment, and a useful one: it works out `x + 1` with the value `x` refers to now, then makes `x` refer to the result.

## Every value has a type

Every value in Python has a *type*, which says what kind of thing it is and so what can be done with it. Four types cover this lesson.

| Type | Holds | Written as |
| --- | --- | --- |
| `int` | a whole number, exactly, however many digits it has | `1024`, `-3`, `0` |
| `float` | a number with a point, to about 16 significant figures | `0.1`, `5.0`, `2.5e-3`, `1e16` |
| `str` | text, a *string* of characters between quotes | `"lr"`, `'1024'` |
| `bool` | a truth value | `True`, `False` |

`2.5e-3` is M1.1's $2.5 \times 10^{-3}$, typed in Python's notation, where `e` means "times ten to the power". An `e` always makes a float, even for a whole number, so `1e16` is a float. `print` writes a float back with an `e` only when it is $10^{16}$ or more, or less than 0.0001, so `print(2.5e-3)` shows `0.0025` and `print(1e16)` shows `1e+16`. `type` names the type of any value: `print(type(0.1))` shows `<class 'float'>`. And the type decides what an operation means.

To mix them, say which you mean by changing the type yourself, a *conversion*: `int("3")` is the int 3, `float("2.5")` is the float 2.5, and `str(4)` is the string `"4"`. So `int("3") + 4` is 7, and `"3" + str(4)` is `"34"`.

Between text and numbers Python never converts by itself, but between kinds of number it does. Arithmetic that mixes an int with a float gives a float, so `2 * 0.5` is `1.0`. And two operations give a float even from two ints: `/`, even when the division comes out whole, so `10 / 2` is `5.0`, and a negative power, so `2 ** -1` is `0.5`. To stay with whole numbers there are two more operations. `//` divides and rounds down to a whole number, and `%` gives the remainder, so `7 // 2` is 3 and `7 % 2` is 1, since $7 = 3 \times 2 + 1$.

## The order Python works in

Python reads every expression as a tree, as M1.2 did on paper, and it fixes the tree with rules much like the order of operations, called *precedence*. From first to last:

1. anything in brackets;
2. powers, written `**`, so $2^3$ is `2 ** 3`;
3. `*`, `/`, `//` and `%`;
4. `+` and `-`.

## What a float really holds

M1.2's calculator kept three significant figures and rounded after every operation, which is how it lost a small number added to a large one. M1.2's puzzle went further: a computer found that $(0.1 + 0.2) + 0.3$ and $0.1 + (0.2 + 0.3)$ differ, and the reason given was that it cannot even store 0.1 exactly. A float keeps about 16 significant figures, so its rounding is far smaller. But is it ever exact?

Computers write numbers in *binary*, with only the digits 0 and 1. Each place is worth twice the one to its right, 1, 2, 4, 8 and so on, just as decimal places are worth 1, 10 and 100. So $13 = 8 + 4 + 1$ is 1101 in binary, four binary digits. A whole number has $k$ binary digits when it is at least $2^{k-1}$ and less than $2^k$: 13 lies between $2^3 = 8$ and $2^4 = 16$. After the point the places are worth $\frac{1}{2}$, $\frac{1}{4}$, $\frac{1}{8}$ and so on, so $0.625 = \frac{1}{2} + \frac{1}{8}$ is 0.101 in binary.

A float holds exactly the numbers of one form: a whole number of at most 53 binary digits, times a power of two, such as $\frac{5}{8} = 5 \times 2^{-3}$. 0.1 is $\frac{1}{10}$, and $10 = 2 \times 5$, so no power of two in the denominator will do. In binary, $\frac{1}{10}$ goes on for ever, $0.000110011001100\ldots$, just as $\frac{1}{3} = 0.333\ldots$ does in decimal. So Python stores the nearest float instead, $\frac{3{,}602{,}879{,}701{,}896{,}397}{2^{55}}$, which is a little more than 0.1.

53 binary digits are worth about 16 decimal figures, since $2^{53}$ is about $9 \times 10^{15}$. When you print a float, Python shows the shortest decimal that leads back to the same float. That is why `print(0.1)` shows `0.1`, although the float is not exactly 0.1, and why `print(0.1 + 0.2)` shows `0.30000000000000004`: that sum lands on a different float from the one for 0.3.

A float can hold a whole number exactly too, as long as it fits. Every whole number below $2^{53} = 9{,}007{,}199{,}254{,}740{,}992$ has at most 53 binary digits, so a float holds it exactly, and so does $2^{53}$ itself, which is $1 \times 2^{53}$. Beyond that, the floats begin to thin out.

The figure above now takes any number you type. Type `1e16` into it to see the gap of 2. So `1e16 + 1` is not a float: it lies exactly halfway between `1e16` and the next float up, $10^{16} + 2$. On such a tie, Python keeps the float whose 53-digit whole number is even. Here that is `1e16` itself, since $10^{16} = 5 \times 10^{15} \times 2$ and $5 \times 10^{15}$ is even, while $10^{16} + 2 = (5 \times 10^{15} + 1) \times 2$. So `1e16 + 1 - 1e16` is `0.0`. An int has no such limit: `10 ** 16 + 1` is exactly 10,000,000,000,000,001.

## The names

<Definition term="Value and type">

A *value* is a piece of data that a program works with, such as `1024`, `0.1`, `"lr"` or `True`. Its *type*, such as `int`, `float`, `str` or `bool`, decides what an operation means for it: `+` adds two numbers but joins two strings. Python never turns text into a number, or a number into text, unless it is told to, as in `int("42")`. Between numbers it converts by itself: an int mixed with a float gives a float, and `/` always gives a float.

</Definition>

<Definition term="Variable and assignment">

A *variable* is a name that refers to a value. An *assignment* such as `x = x + 1` works out its right side with the values the names refer to at that moment, then makes the name on the left refer to the result. The name keeps the value, never the formula that made it.

</Definition>

<Definition term="Precedence">

The rules that fix an expression's tree: brackets first, then powers, grouped from the right, then a minus sign in front, then `*`, `/`, `//` and `%`, then `+` and `-`, each of the last two levels grouped from the left.

</Definition>

<Definition term="Binary">

Writing numbers with only the digits 0 and 1, each place worth twice the one to its right: 1101 is $8 + 4 + 1 = 13$, and 0.101 is $\frac{1}{2} + \frac{1}{8} = 0.625$.

</Definition>

<Definition term="Float">

A number stored as a whole number of at most 53 binary digits times a power of two, good to about 16 significant figures. Any other number, such as 0.1, is stored as the nearest float, so two floats that should be equal may differ in their last digits. Big floats are far apart: near $10^{16}$, 2 apart.

</Definition>
