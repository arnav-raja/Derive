## Running a program on paper

Python runs a program with numbers, but you can run one on paper with letters, line by line, exactly as Python would. Take this program, where `a` stands for any number:

```python
x = a
x = x + 3
x = 2 * x
```

Line 1 makes `x` refer to $a$. Line 2 works out `x + 3` with `x` as it is now, $a$, and makes `x` refer to $a + 3$. Line 3 works out `2 * x` with `x` as $a + 3$, so at the end `x` refers to $2(a + 3) = 2a + 6$. A check with a number catches slips: run the three lines after `a = 1` and `x` ends as 8, and $2 \times 1 + 6 = 8$.

Check with a number: after `a = 3`, Python ends with `x` as 49, and $(2 \times 3 + 1)^2 = 49$. The order of the lines matters as much as the lines themselves. Move the squaring up, to just after `x = a`, and the same four lines end with $2a^2 + 1$.

So the program ends with `x` as $b$ and `y` as $a$: the two values have swapped, with no third name. On paper, with exact numbers, the algebra is airtight. With floats it is not. Run it with `a = 0.1` and `b = 1e16`. Line 3 works out $0.1 + 10^{16}$, and near $10^{16}$ floats are 2 apart, so the sum rounds to `1e16` and the 0.1 is lost for good. The program ends with `x` as `1e+16` and `y` as `0.0`. Algebra describes exact numbers, and floats only come close to them.

Python has a swap that loses nothing: `x, y = y, x`. It works out both values on the right first, then gives them to the names on the left, so neither is overwritten before it is used.

## How far apart big floats are

Explore found that near $10^{16}$ neighbouring floats are 2 apart, because a whole number there has one more binary digit than a float can keep. The same reasoning reaches much further up.

So the gap grows roughly in proportion to the numbers. Across almost the whole range of floats, the gap is between about $1.1 \times 10^{-16}$ and $2.2 \times 10^{-16}$ of the number itself, that is, between $2^{-53}$ and $2^{-52}$ of it, which is what "about 16 significant figures" means.

A gap of 16,384 means that `1e20 + 1000 == 1e20` is `True`: 1,000 is less than half a gap, so the sum rounds straight back. A long run of small numbers added one at a time to a huge float total can vanish entirely in this way, which is why M13.2 measures such errors with care.
