## Formulas into Python

On paper, a formula's layout does some of the grouping for you. A fraction bar groups everything above it and everything below it, and an exponent groups everything raised up. In Python a formula is one line of text, so each such group needs brackets of its own. A square root is a power of one half, so $\sqrt{v}$ is `v ** 0.5`.

<Reveal for="build-formulas">

`-x ** 2` is $-x^2$ with no brackets, since the power comes before the minus sign. Each of the others needs brackets for a group that the layout on paper made by itself: the exponent $\frac{1}{3}$ in `27 ** (1 / 3)`, the denominator in `peak_lr / (1 + step / warmup)`, and the denominator again in `peak_lr / (v ** 0.5 + eps)`. Without its brackets, the last one divides by $\sqrt{0}$, and Python stops with `ZeroDivisionError: division by zero`. The tiny `eps` is in the formula precisely so that the division is safe when `v` is 0, as it is at the start of training.

## Ask Python for its tree

Python's `ast` module, short for *abstract syntax tree*, shows the tree that Python builds for an expression. This program

```python
import ast
print(ast.dump(ast.parse("1 + 2 * 3", mode="eval").body))
```

prints

```
BinOp(left=Constant(value=1), op=Add(), right=BinOp(left=Constant(value=2), op=Mult(), right=Constant(value=3)))
```

Read it from the outside in. `BinOp` is an operation with two sides, `left` and `right`, and `op` names it: `Add`, `Sub`, `Mult`, `Div`, `FloorDiv`, `Mod` or `Pow`. `UnaryOp` with `op=USub()` is a minus sign in front, and `Constant` is a number. So the top of this tree is the addition, with the tree for `2 * 3` below it on the right, just as M1.2 drew it.

`((-(2 ** (3 ** 2))) + ((10 // 3) * 2))` has the same tree as the bare expression, and both are worth $-512 + 6 = -506$. Brackets that only spell out the tree Python would build anyway change nothing, so they are always safe. Code that others will read often keeps a few for clarity, as in `-(x ** 2)` or `(a * b) % m`, rather than relying on every reader knowing the rules.

`input()` always gives a string, here `"1024"`, since it cannot know what the typed text was meant to be. Converting at the edge of a program, where text from outside arrives, means that every line after it can trust the type. The same goes for numbers read from a file or a web page.

## Comparing floats

Two floats that should be equal may differ in their last digits, so a program should ask whether two floats are *close enough*, within a tolerance, rather than whether they are exactly equal. `abs(a - b)` is the distance between `a` and `b`. The question is how close is close enough.

A tolerance must be wide enough to forgive rounding, which near 1 is about $10^{-16}$, and narrow enough to catch a real mistake, here $10^{-4}$. `math.isclose(a, b)` is Python's standard check: it is `True` when `a` and `b` differ by at most a billionth of the larger of the two, so they agree to about 9 significant figures. Rounding with `round(total, 2) == 1`, or allowing a difference of 0.01, would have let the mistake through. Reordering the sum until `==` happens to say `True` is worse still, since the next sum will not be so lucky.
