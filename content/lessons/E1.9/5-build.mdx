The Derive phase reasoned about tests without running any. Now build the tools of testing: a runner for a suite, a test that tells a right median from wrong ones, a property-based test, and a shrinker with a bug of its own. On the way, predict what one change does to a test of floats.

Each exercise in this phase has tests of its own, in the tab `tests.py`, and they are run as this lesson's runner runs a suite: each is a function whose name begins with `test_`, called inside a `try`, and one whose assert fails shows you the assert's message. You need not read their code, which uses some Python that this lesson does not teach.

## A test of floats

<Exercise id="breakit-isclose" />

</Reveal>

<Reveal for="breakit-isclose">

A test of floats must allow for rounding, or it fails on code that is right, and a test that fails for no reason soon stops being believed, so its real failures are missed too. `math.isclose`, which E1.1 used, allows a difference of about a billionth of the larger value, so near 0 it needs a tolerance of its own: `math.isclose(0.1 + 0.2 - 0.3, 0)` is `False`, while `math.isclose(0.1 + 0.2 - 0.3, 0, abs_tol=1e-9)` allows a difference of a billionth and is `True`. Whole numbers and strings have no rounding, so their tests can use `==`.

With the seed 1, the very first list breaks the property: `check` gives `[3, 10, 2, 5, 2]`, and the Explore phase's shrinker takes it down to `[2, 2]`. Hypothesis does the same work with far more care: it shrinks every failing input it finds, and it saves each one, so that the next run tries it first.
