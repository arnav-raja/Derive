## Proving what a loop prints

Explore found that `lr * 2 ** halvings` is 1 before the puzzle's loop starts and after every pass. Write $h$ for the value of `halvings`, so the invariant says $\texttt{lr} \times 2^h = 1$. When the loop stops, the test `lr > 0.001` has also just been found `False`. Put the two together, and the loop's answer follows without running it.

<Exercise id="derive-halving-proof" />

<Reveal for="derive-halving-proof">

The invariant turns a question about running the loop into a question about numbers. The loop stops at the first $h$ with $2^h \ge 1{,}000$, and the first power of two that large is $2^{10} = 1{,}024$, so the program prints 10. Nothing had to run. The floats in this loop are exact, too: `lr` is always a power of two, which a float holds exactly, so the proof describes what Python really does.

## Any rate that shrinks by a factor

The same argument works for any schedule that multiplies the rate by one fixed factor on every pass:

```python
lr = a
passes = 0
while lr > floor:
    lr = lr * r
    passes = passes + 1
```

Here `a` is the starting rate and `r` is a number between 0 and 1, such as 0.5 for halving or 0.9 for a gentler schedule. Write $h$ for the value of `passes`. The first step is to find the invariant.

`lr` is $a r^h$ at every check. It starts as $a = a r^0$, and each pass multiplies it by one more factor of $r$, since $a r^h \times r = a r^{h+1}$. When the loop stops, its test has failed as well, so it stops at the first $h$ with $a r^h \le$ `floor`. For the puzzle, with $a = 1$ and $r = \frac{1}{2}$, that is the first $h$ with $\frac{1}{2^h} \le 0.001$, which is 10 again.

Ten halvings shrink a number by a factor of $2^{10} = 1{,}024$, a little more than a thousand. That one fact makes other floors quick to estimate.

$10^{-9}$ is $10^{-3} \times 10^{-3} \times 10^{-3}$, and each factor of $10^{-3}$ takes about 10 halvings, so it takes about 30. It is in fact exactly 30, since $2^{30} = 1{,}073{,}741{,}824$ is the first power of two past $10^9$, while $2^{29} = 536{,}870{,}912$ falls short. Computing uses the same near-match all the time: $2^{10}$ bytes, a kibibyte, is close to a thousand bytes, and $2^{30}$ bytes is close to a billion.

## A running total, proved

The same method proves what Explore's running total computes. Here it is for any whole number $n$:

```python
total = 0
for k in range(1, n + 1):
    total = total + k
```

Here is a claim: after the pass for $k$, `total` is $\frac{k(k+1)}{2}$. Before the first pass, `total` is 0, which is the claim with $k = 0$. Now suppose the claim is true after the pass for some $k$. The next pass adds $k + 1$.

</Reveal>

<Reveal for="derive-sum-step">

The new total is $\frac{(k+1)(k+2)}{2}$, the claim again with $k + 1$ in place of $k$. So the claim is true before the first pass, and every pass keeps it true: it is an invariant. The last pass is the one for $k = n$, so the loop ends with

$$
\texttt{total} = \frac{n(n+1)}{2}.
$$

For $n = 4$ that is 10, as Explore's figure printed, and for $n = 100$ it is 5,050. The loop and the formula agree for every $n$, and the invariant is the proof: no amount of running the loop for particular values of $n$ could show that.
