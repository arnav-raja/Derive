## An iterator by hand

A generator is the short way to write an iterator. The long way is a class, and it shows exactly what a `for` loop calls. `for x in c:` first calls `iter(c)`, which calls `c.__iter__()`, and then before every pass calls `next` on what that gave back, which calls its `__next__()`. An iterator's `__iter__` gives back the object itself. Its `__next__` gives the next value, or, when there is none, runs the line `raise StopIteration`. `raise` makes an error happen on purpose: a bare `next` would stop the program with it, as in the Explore phase, while a `for` loop takes it as its signal to stop.

`Countdown` keeps its place in `self.n`, as a file keeps its place in the text, so it is used up after one loop, like every iterator. To make an object that can be looped over again and again, as a list can, give it an `__iter__` that makes a fresh iterator each time. A generator does that in a few lines: an `__iter__` written with `yield` gives a new generator on every call, starting from the top.

```python
class Repeatable:
    def __init__(self, n):
        self.n = n

    def __iter__(self):
        n = self.n
        while n > 0:
            yield n
            n = n - 1


r = Repeatable(3)
print(list(r), list(r))
```

This prints `[3, 2, 1] [3, 2, 1]`: each `list` calls `iter(r)`, which runs `__iter__` again and makes a new generator, while `r` itself never changes.

## Packing documents

A language model reads each token as a whole number, its *token id*, and trains on sequences of a fixed number of tokens, 2,048 for GPT-3, while documents come in every length. So the documents are *packed*: their tokens are laid end to end, with a token that marks the end of each document, and the stream is cut into sequences of exactly the right length. GPT-3's paper describes doing this, to make training more efficient, with a special end-of-text token between documents.

A document longer than a sequence is split across two or more, and a sequence may hold the end of one document and the start of the next. The model learns from the end token where one document stops and the next begins.

## Mixing streams

A training set mixes data from several sources, such as web pages, books and code, each its own stream. The simplest mix takes one item from each stream in turn. Since a stream may be a file or a generator, each must be asked for its items through one iterator, made once with `iter` and kept. `next(it, default)` tells when a stream has run dry. `object()` makes a new object that is equal to nothing else, which makes a safe default: after `done = object()`, `next(it, done) is done` is `True` only when `it` has nothing left, whatever values the stream holds, `None` included.
