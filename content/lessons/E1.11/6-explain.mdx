## Where this leads

A `for` loop asks for an iterator and calls `next` until there is nothing left. Everything in this lesson, from the used-up file to the shuffle buffer, followed from that one protocol and from generators that make each value only when it is asked for.

<Foreshadow lesson="E5.5">

PyTorch's `DataLoader` is an iterable, not an iterator: each `for` over it makes a fresh iterator, so every epoch sees all the data. E5.5 opens it up, with datasets that hand out one example at a time, batches put together from them, and worker processes that prepare the next batches while the current one trains.

</Foreshadow>
