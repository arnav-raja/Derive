## A tokeniser for any script

The Explore phase's tokeniser keeps only what `isalpha` calls a letter, so it cuts नमस्ते at its marks, leaves out digits, and splits "don't" in two. `unicodedata.category(ch)` names the category of the character `ch`, and its first letter, `unicodedata.category(ch)[0]`, is `L` for a letter, `M` for a mark and `N` for a digit or another number, such as ½, in every script. Inside a string, `\u` and four hexadecimal digits stand for the character with that number, so the tests write an e followed by U+0301, an accent that is a mark, as `"é"`.

The property holds for the Explore phase's tokeniser, though that tokeniser is wrong: it cuts नमस्ते at its first mark and drops the second, whether the word stands alone or not. A property says one thing that must always be true, and a tool that is wrong in the same way everywhere keeps it. So a tool needs both kinds of test: examples, such as नमस्ते, that say exactly what is right, and properties, which try thousands of inputs that nobody thought of.

## Break it: two ways to type é

é can be typed as one code point, U+00E9, or as two, an e followed by U+0301, an accent that is a mark, as some keyboards and programs type it; in Python the second is `"é"`, as the tokeniser's tests wrote it. On screen the two look the same, and Unicode counts them as the same text. `unicodedata.normalize("NFC", text)` puts a text in one standard form, called NFC, in which every way of typing é becomes the single code point U+00E9. A few characters go the other way: NFC writes क़ as क followed by the mark ़, however it was typed. This word count puts each word in NFC before it counts it. Take that step out.

A tool should put the whole text in NFC once, as it reads it, before it cuts it into words: `text = unicodedata.normalize("NFC", text)`. Text gathered from the web comes in both forms, and cleaning it for a language model includes this step. NFC joins only what Unicode counts as the same text, though: a Latin a and a Cyrillic а look alike, and stay different.

Put together, the parts are the tool: `text = unicodedata.normalize("NFC", text)` as the text is read, then `words = tokens(text)`; `top_words(word_counts(words), 10)` for the commonest words; `count_sentences(text)`; and `generate(next_counts(words), "the", 8)`. On *Alice* it finds 26,688 words, 2,630 of them different, and 1,585 sentences, ranks "the", "and" and "to" first, and writes "the queen and the queen and the queen". Each part keeps its contract and its tests, so any one of them can be rewritten without touching the rest, as E1.3 found.
